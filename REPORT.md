# Итоговый отчёт: развёртывание и мониторинг audit-svc

## Задание 1. Сборка и публикация образа в CI
- Успешно настроен многоступенчатый (multistage) `Dockerfile` с запуском от непривилегированного пользователя `appuser` (UID 1000).
- Настроен пайплайн GitHub Actions (`.github/workflows/deploy.yml`), который выполняет тестирование через `pytest`, сборку и публикацию Docker-образа в реестр GHCR (`ghcr.io/konstantinstan/final-dz`).

## Задание 2. База данных и секреты
- На целевой машине через Ansible развёрнут контейнер `postgres:17` с данными в томе.
- С помощью задач Ansible автоматически созданы база данных `audit_svc` и выделенный пользователь `audit_svc` (владелец БД).
- Секреты (пароли суперпользователя и сервиса) зашифрованы с помощью `ansible-vault` в файле `vault.yml` и расшифровываются в CI с помощью защищённой переменной `ANSIBLE_VAULT_PASSWORD`.

## Задание 3. Развёртывание из CI и перечитывание конфига
- Развёртывание выполняется Ansible-плейбуком `audit-svc.play.yml` при пуше тега `v*`.
- Проверена идемпотентность и корректность работы хендлера перечитывания конфигурации (`/reload`), позволившая обновить пароль базы данных без перезапуска контейнера `audit-svc`.

## Задание 4. Nginx и nginx-exporter
- Порт наружу (`8088`) публикует только Nginx; сервисы и PostgreSQL изоляции находятся во внутренней сети `audit-net`.
- Защита путей: прямой запрос к `/reload` возвращает `404 Not Found`.
- Подключен `nginx-prometheus-exporter`, метрика `nginx_up` успешно возвращает `1`.

## Задание 5. Prometheus и дашборды в Grafana
- Запущен стек мониторинга (Prometheus + Grafana), подключенный к внешней сети.
- Сгенерирована нагрузка через утилиту `generate`, метрики сервиса успешно собираются через Nginx.
- Созданы кастомные JSON-дашборды для отображения событий в секунду (`audit_events_received_total`), HTTP-кодов ответов и статуса `up`.
